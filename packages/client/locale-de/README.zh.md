# @deepseek-ai/dsh-client-locale-de

[English](README.md) | 中文

## 概述

使用 `dsh-client-locale-de` 以德语运行 Web GUI。本包注册 `de` 语言，并为已随附 Web 客户端清单渲染的每一个命名空间提供一份德语词典；「设置 → 通用」的语言行随后把 **Deutsch** 与内置的 中文、English 并列显示，选中后整个界面立即切换。本包未覆盖的键通过语言服务的回退链解析到英语，因此新增了界面文案的命名空间会为缺失键显示英语，而不是原始键名。

## 使用本包

无需任何配置。本包随 `dsh-web-app` 组合包的客户端树一起激活，其浏览器半身以受管理的 effect 注册语言定义与全部词典。打开「设置 → 通用」并选择 **Deutsch**；该选择与其它语言偏好一样持久化到 `$DSH_HOME/settings.yaml`，`<html lang>` 会指向 `de`。

从组合包补丁中移除 `locale-de` 行（或卸载本插件）会从选择器中移除该语言，并把处于激活状态的德语选择回退到浏览器派生或默认语言。

## 实现说明

本包不拥有任何界面：不注册插槽、不渲染内容。它只是 `locale` 服务上的词典贡献方：

- `src/client/locales/index.ts` 把每个命名空间 id 映射到其德语词典（`DE`），并导出语言 id 与自述标签。
- `src/client/locales/<命名空间>.ts` 存放单个命名空间的词典。键逐字复制自各命名空间的英语源，包括 `{placeholder}` 占位符；只有值是德语。
- `src/client/index.ts` 在 `ctx.effect` 中调用 `ctx.locale.addLanguage({ id, label, fallback: 'en' })` 与每个命名空间的 `ctx.locale.register(ns, 'de', dict)`，因此销毁会同时撤销两者。

使用非类型化的单语言 `register` 形式是刻意为之：命名空间的键类型联合归拥有它的功能包所有，而语言包只贡献一种语言、并不补齐内置语言对，因此类型化的 `Record<BuiltInLocaleId, …>` 形式并不适用。

## Model Experience

无。语言包不注册任何模型可见内容，只贡献浏览器侧界面文案。

#### KV Cache effect

无；本包既不组装也不发送提供方请求。

## 已知限制与延期工作

以下限制说明德语翻译在构造上不完整或可能漂移之处。它们是本包当前的约束，而非待办事项。

- **键完整性不被编译期检查。** 命名空间的类型化键联合属于拥有它的功能包，因此当该功能包新增英语键而没有德语对应项时，构建不会失败。查找链会为缺失键渲染英语。针对英语源的键一致性审计是功能包发布新界面文案后的维护步骤。
- **注册期捕获的文本只读取一次翻译。** 在插槽渲染路径之外于注册期捕获的文案（例如命令描述）会保持其注册时的语言，直到重新注册；这是语言服务已记录的约束，所有语言包都同样继承。
- **无复数规则或双向排版。** 语言注册表只提供选择、持久化与键回退；德语复数通过各命名空间已定义的 `one`/`other` 键对表达，德语也不需要 RTL 处理。

**运行时不变量：** 未发布任何伴随校验。词典没有可比较的独立运行时来源；注册、查找与销毁均由行为规格断言。
